# Проект AI Factory 1.0

**Статус:** проектная документация для рассмотрения; реализация не входит в текущий этап.  
**Основа:** [`../specification.md`](../specification.md), требования P-001–P-048 и сценарии A-01–A-15.  
**Метод:** Superpowers (obra/superpowers), этапы выявления требований, проектирования и составления плана. Навык не установлен в рабочем окружении, поэтому метод применён вручную; реализационные навыки TDD и review не запускались.

## Решение в кратком виде

Для первого релиза предлагается использовать OpenAI Agents API как управляемую среду сессий и оркестрации, OpenAI-hosted sandbox как эфемерную рабочую среду, а GitHub — как долговременный источник истины. Верхнеуровневый агент PO определяет структуру работы и создаёт задачи; необязательные Chief и Planner появляются только при обоснованной нагрузке. Подчинённые агенты получают ограниченные назначения. Для запуска и продолжения сессий предполагается внешний вызов API из короткоживущего инициатора (например, ручной запуск человеком или stateless GitHub Actions workflow); постоянный собственный сервер не нужен.

Рабочая копия репозиториев, файлы и процессы sandbox считаются временными. Задачи могут возобновляться в существующей сессии, пока сессия и среда доступны; для восстановления после потери среды обязательны checkpoint в GitHub и возможность начать новую сессию из манифеста и коммитов. Артефакты сначала публикуются в отдельных ветках репозиториев; приёмка и слияние выполняются независимо, а журнал согласования фиксирует частичный успех.

Это целевая архитектура, не подтверждение, что все API-пути и ограничения аккаунта доступны конкретному заказчику. Проверяемые возможности и обязательные прототипы описаны в [проверке платформы](platform.md). До успешного прототипа GitHub-доступа, двух репозиториев, делегирования с разными ролями/моделями и восстановления реализация не должна считаться готовой.

## Как читать решения и неопределённость

В документах обозначения **Проверено** означают подтверждение публичной документацией OpenAI на дату исследования (18.10.2026), но не гарантируют включение возможности в конкретный аккаунт, квоты, тариф или организационную политику. **Проектное решение** — предлагаемая конструкция. **Проверить прототипом** — критичная зависимость, для которой документации недостаточно. **Требует решения заказчика** — вопрос, который меняет пределы полномочий, данные, стоимость или выпуск; он не решается агентом самостоятельно.

Открытые вопросы, блокирующие финальное утверждение дизайна:

1. Какой именно облачный контур и тип учётной записи будет использоваться: Agents API с оплатой API либо Codex/ChatGPT с подписочной квотой? Предложение предполагает Agents API и не переносит сюда квоты подписок.
2. Допустимы ли GitHub Actions как необязательный статeless инициатор сессий, если производственная среда и агенты остаются в облаке провайдера?
3. Может ли проектная спецификация включать чувствительные материалы в OpenAI Agents API, учитывая текущие ограничения по хранению и резидентности? До решения использовать только несекретные тестовые репозитории.
4. Какой режим слияния утвердить для двух репозиториев (PR с human review либо автоматическое слияние после приёмки)? По умолчанию предлагаются отдельные PR; автоматическое изменение защиты и публикация запрещены.

Эти вопросы не меняют принятые требования; при отрицательном ответе требуется пересмотреть механизм, сохранив требования P-001–P-048.

## Словарь

| Термин | Значение |
|---|---|
| Фабрика | Общие роли, правила, инструменты и история развития, хранящиеся в репозитории фабрики. |
| Целевой продукт | Внешнее приложение, спецификация и исходный код которого находятся в отдельном репозитории. |
| Запуск (run) | Полный производственный цикл для одного проекта; имеет стабильный `run_id`, даже если включает несколько облачных сессий. |
| Сессия (session) | Состояние агента у провайдера. Сессия может переживать отдельные ходы/turns, но не заменяет Git как долговременную запись. |
| Ход (turn) | Один цикл работы агента в сессии. |
| Задача (task) | Ограниченная единица работы с одним ответственным менеджером, критериями приёмки и лимитом ресурсов. |
| Направление | Область продукта или эпик, назначенный одному Planner. |
| Checkpoint | Записанное состояние, достаточное для восстановления задачи или запуска после остановки. |
| Действующая инструкция | Совокупность общих и локальных инструкций, полномочий и версий, реально применённая при назначении. |
| Данные-основания (evidence) | Факты, коммиты, результаты проверок, ошибки и метрики, подтверждающие решение; неизвестное явно помечается. |
| Принято | Результат прошёл проверки прямого руководителя; интегрированный продукт отдельно принимает PO. |
| Ожидание | Восстанавливаемое состояние из-за квоты, решения, внешней зависимости или окна выполнения. |
